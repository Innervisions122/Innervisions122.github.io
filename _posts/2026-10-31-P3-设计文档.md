# 简单 MIPS 单周期处理器设计文档

总共实现了 `add` `sub` `ori` `lui` `lw` `sw` `beq` `j` 指令。

## 1. 指令格式

### 1.1 R 型指令


    | 31-26      | 25-21  | 20-16  | 15-11  | 10-6     | 5-0       |
    ----------------------------------------------------------------
    | opcode (6) | rs (5) | rt (5) | rd (5) | shamt(5) | funct (6) |


用于 `add` 和 `sub`。

### 1.2 I 型指令

    | 31-26      | 25-21  | 20-16  | 15-0           |
    -------------------------------------------------
    | opcode (6) | rs (5) | rt (5) | immediate (16) |

用于 `ori` `lui` `lw` `sw` `beq`。其中 `ori` `lui` `lw` 写入 `rt`；`sw` 将 `rt` 的数据写入内存；`beq` 比较 `rs` 与 `rt`。

### 1.3 J 型指令

    | 31-26      | 25-0             |
    ---------------------------------
    | opcode (6) | instr_index (26) |

用于 `j`。26 位地址字段左移两位，再与高 4 位地址拼接，形成 32 位跳转目标。





## 2. GRF

已在 P0 完成。

## 3. PC：程序计数器

PC 模块保存当前指令的字节地址。

通过异或门的操作给寄存器赋初值 `0x3000`。

## 4. NPC：下一条指令地址生成

分为 `PC + 4` `j` `beq` 几种情况，由 `zero` 判断是否 `beq`，由 `NPC_sel` 判断应输出哪种情况。

## 5. IM：指令存储器

IM 使用 ROM 保存机器码，输入为 32 位 PC，输出为 32 位指令。

ROM 中指令机器码的首地址是 0 ，而不是 0x3000 ，所以在将地址输入 ROM 之前，需要减去一个 0x3000。ROM 相邻两条指令之间的输入值相差 1，所以在 -3000 之后，还需要再除以 4，也就是右移 2 位。

其处理过程为：

```text
相对字节地址 = PC − 0x00003000
ROM 地址     = 相对字节地址[17:2]
```

低两位被去掉，将字节地址转换为字地址；由于 ROM 自身限制，高于第 17 位的部分不参与 ROM 寻址。

## 6. Controller：控制器

Controller 为组合逻辑模块，输入 opcode（6 位）和 func（6 位）。内部通过比较器判断指令类型；R 型指令还将 opcode=0 与功能码匹配结果相与。各指令识别信号送入优先编码器，再通过多路选择器生成控制信号。

以下是所有输出的接口：

| 输出 | 位宽 | 作用 |
|---|---:|---|
| NPC_sel | 2 | 选择顺序、j 或 beq 地址 |
| ALU_instr | 4 | 指定 各个指令在 ALU 中的操作 |
| WE | 1 | GRF 写使能：add，sub，ori，lui，lw |
| sw_WE | 1 | DM 写使能：sw |
| which_A | 1 | 0 选择 rd，1 选择 rt，作为 A3：ori，lui，lw |
| lw | 1 | 0 选择 ALU Result，1 选择 DM Data，作为写回数据 |
| extend | 1 | 0 选择 GRF RD2，1 选择立即数，作为 ALU 的 B 输入 |
| RD2 | 2 | 立即数类型选择：0 零扩展、1 符号扩展、2 高位加载：ori，lui，lw，sw |

### 6.1 控制信号表

下表为当前电路的控制编码。`x` 表示该指令不使用此选择信号。

| 指令 | ALU_instr | NPC_sel | WE | sw_WE | which_A | lw | extend | RD2 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| add | 1 | 0 | 1 | 0 | 0 | 0 | 0 | x |
| sub | 2 | 0 | 1 | 0 | 0 | 0 | 0 | x |
| ori | 3 | 0 | 1 | 0 | 1 | 0 | 1 | 0 |
| lui | 4 | 0 | 1 | 0 | 1 | 0 | 1 | 2 |
| lw | 5 | 0 | 1 | 0 | 1 | 1 | 1 | 1 |
| sw | 6 | 0 | 0 | 1 | 0 | 0 | 1 | 1 |
| beq | 7 | 2 | 0 | 0 | 0 | 0 | 0 | x |
| j | 8 | 1 | 0 | 0 | 0 | 0 | 0 | x |

## 7. ALU：算术逻辑单元

ALU 接收两个 32 位操作数及 4 位 ALU_instr，输出 32 位 Result 和 1 位 zero。

| ALU_instr | 对应指令 | 功能 |
|---|---|---|
| 1 | add | `Result=A+B` |
| 2 | sub | `Result=A−B` |
| 3 | ori | `Result=A OR B` |
| 4 | lui | `Result=B`，B 已在顶层左移 16 位 |
| 5、6 | lw、sw | `Result=A+B`，形成有效字节地址 |
| 7 | beq | `zero=(A==B)` |
| 8 | j | Result 和 zero 均不参与该指令执行 |

## 8. DM：数据存储器

DM 使用 RAM保存 lw/sw 访问的数据。

| 接口 | 方向 | 位宽 | 含义 |
|---|---|---:|---|
| Addr | 输入 | 32 | ALU 计算的有效字节地址 |
| WriteData | 输入 | 32 | 待存储数据，来自 GRF RD2 |
| WE | 输入 | 1 | 存储器写使能，来自 sw_WE |
| clk、reset | 输入 | 1 | 时钟和清零控制 |
| Data | 输出 | 32 | 读出的存储字 |

## 9. 顶层观察接口

| 接口 | 位宽 | 观察位置 |
|---|---:|---|
| Instr | 32 | IM 的指令输出 |
| pc | 32 | PC 模块的当前地址输出 |
| RegWrite | 1 | GRF 写使能 |
| RegAddr | 5 | GRF A3 |
| RegData | 32 | GRF WD |
| MemWrite | 1 | DM WE |
| MemAddr | 32 | DM Addr，保留完整字节地址 |
| MemData | 32 | DM WriteData，表示写入内存的数据 |
| reset | 1 | 输入信号，分发到 PC、GRF、DM |

## 11. 思考题

1.上面我们介绍了通过 FSM 理解单周期 CPU 的基本方法。请大家指出单周期 CPU 所用到的模块中，哪些发挥状态存储功能，哪些发挥状态转移功能。

> `GRF` `PC` `DM` 储存，`NPC` `ALU` `Controller` 状态转移。

2.现在我们的模块中 IM 使用 ROM， DM 使用 RAM， GRF 使用 Register，这种做法合理吗？ 请给出分析，若有改进意见也请一并给出。

> 合理。（1）IM 使用 ROM，结构简单、容易实现，且避免了程序意外修改指令。（2）DM 既需要执行 lw 读取数据，又需要执行 sw 写入数据，因此须采用可读写存储器。（3）GRF 既要进行读取，又要进行写入，所以采用寄存器。为什么 RAM 不好呢？因为 GRF 需要同时读取两个寄存器、写入一个寄存器，而普通 RAM 通常不具备这样的多端口读写能力。

3.在上述提示的模块之外，你是否在实际实现时设计了其他的模块？如果是的话，请给出介绍和设计的思路。

> 没有。而 IFU 模块我直接在 main 里实现了。

4.事实上，实现 nop 空指令，我们并不需要将它加入控制信号真值表，为什么？

> 因为 nop 指令不需要对寄存器或数据存储器进行任何修改，只需要让 PC 正常加 4，此时所有控制信号置低电平，没有影响。

5.阅读 MIPS 单元“6.1 测试程序设计”一节中给出的测试样例，评价其强度（可从各个指令的覆盖情况，单一指令各种行为的覆盖情况等方面分析），并指出具体的不足之处。

> 指令种类覆盖较全，强度一般。缺点有 sub 缺少接收非零减数的结果、负结果、相减为零的结果；ori 的源寄存器要么为零，要么低 16 位为零，不能与按位异或、加法区分；lw，sw 四条访存指令的有效地址都是 4，可以再多写几种不同的情况。

> 同时 AI 指出，beq 的基本行为覆盖较好，但失败判定不够明确；部分测试结果被覆盖，最终状态无法证明它们执行正确。
